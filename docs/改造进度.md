## 二、每一步到底改了什么

### 第 0 步 · token 体系 ✅

- `lib/core/theme/app_colors.dart`：基底/表面/三级文字/强调/状态色/分割线
- `lib/core/theme/app_typography.dart`：`title` / `body` / `caption` + OSD 专用 `osdNumber` / `osdCaption`
- `lib/core/theme/app_density.dart`：面板高、台标、按钮直径、行高、间距、圆角，按 TV/桌面/手机三档；`DeviceProfileScope` 同时下发用户字号滑块系数
- 数值全部按 **1.0.201 实测观感校准**（面板大字 24、节目行 14.5、台标 128/92、按钮 48/44），先贴合现状再谈优化

### 第 1 步 · 焦点协调器 🟡

`lib/core/focus/` 下三个文件（`focus_region` / `focus_coordinator` / `safe_focus`）已入库。

**为什么不接**：1.0.201 已经是「单根焦点 + 全局按键分发」结构，没有旧版那些"每个面板各挂一套 onKeyEvent、抢焦点"的补丁，`player_screen.dart` 里一处分发就能覆盖面板/列表/EPG/数字输入。此时再插一层协调器，等于把一个能用的东西重写一遍，收益是"更整齐"，代价是全局焦点回归风险。按"简洁快速"原则先不动，如果后续真的出现焦点互抢再加。

### 第 2 步 · token 全量替换 ✅

- 底部面板：字号、间距、按钮尺寸、圆角已全部走 token
- 频道列表 / EPG：新增三个列表专用槽 `listHeader` / `listItem` / `listSub`
  （18 / 16 / 12.5），把抽屉标题、分类名、频道名、频道号、节目名、
  节目时间、直播中徽章、描述等 14 处字面量全部换掉。
  三档目前取同一组值：列表是「密度优先」界面，字号和行高是一对
  （`AppDensity.listRowHeight`），单改字号会改变一屏频道数。
  以后要按电视/手机差异化，只改这张表 + 对应行高即可。

### 第 3 步 · ghost 统一按钮 ✅（本轮）

`lib/core/widgets/ghost_button.dart` 重写：

- 尺寸只来自 `AppDensity.buttonSize`，组件外不能传尺寸；`role` 决定倍率（普通 1.0 / 强调 1.25 / 主控 1.2）
- 新增 `selected`：外部高亮（遥控器 ←/→ 选中）与键盘焦点、鼠标悬停**共用同一套视觉**——白描边 + 细发光 + 8% 白底
- 修掉旧实现的一个真 bug：原来用 `Focus.of(context)` 判断焦点，拿到的是**祖先**节点，按钮自己聚焦时永远返回 false，等于焦点态从没生效过。现在改为自持 FocusNode 监听
- Tooltip 只在桌面端启用（电视/手机没有悬停，提示反而挡画面）
- 桌面端 tooltip 自动追加真实快捷键：`暂停 (空格)` / `静音 (M)` / `全屏 (F)` / `录制 (R)`

接入点：

- `lib/widgets/bottom_program_panel.dart`：删掉 `IconButton` + `_wrapSelected` 蓝框高亮，全部换 `GhostButton`
- `lib/player/widgets/source_stepper.dart`：左右箭头同样换掉，消除"箭头蓝框、别的钮白框"的混搭

### 第 4 步 · 底部面板重排 ✅

`lib/widgets/bottom_program_panel.dart`：悬浮卡片式面板（深色渐变 + 圆角 + 细描边 + 投影）、台标不贴左缘、信息区可挤压截断、`‹ 线路 n/m ▾ ›` 步进器（点中间弹线路菜单跳选）、分组竖线（电视/桌面有，手机不画）。

### 第 5 步 · 换台防抖 + 数字输台 ✅

- 换台两段式：先只更新 OSD 预览，**450ms 内不再按键才真正切流**，连续上下键不再把中间频道全都拉一遍流
- 数字输台：2s 自动提交、每次按键先清缓冲防残留、`startsWith` 部分匹配给灰字提示、无匹配提示"无此频道号"

### 第 6 步 · 播放哨兵 ✅ 原生已有

1.0.201 自带投屏看门狗、有声无画检测、软→硬分级重载与重载上限提示，不重复实现。

### 第 7 步 · 投屏态 + 安卓浮窗 ✅

- 面板 castMode：信息区换「正在投屏 · 设备名」，按钮组换播放/静音/旋转/断开
- 安卓：`supportsPictureInPicture` + 前台服务 + 通知栏音频卡片（上一台/暂停/下一台/关闭），退后台自动进小窗；相关原生代码由 CI 在 `flutter create` 后注入，Dart 侧门面是 `lib/services/pip.dart`

### 第 8 步 · Windows 快捷键 ✅ 原生已有

已注册：空格=暂停、↑↓=换台（走防抖）、←→=换源、M=静音、F/F11=全屏、R=录制、C=频道、E=节目单、S=设置、数字=跳台、Esc=层级返回。

> 注意：`R` 实际是**录制**，不是重载。重载按钮没有快捷键，别在提示里写错。

### 第 9 步 · 设置页双栏（方案 4.1）✅

- 顶部四/五 Tab → **左栏分类 + 右栏内容**：节目源 / EPG / 播放器 / 系统 / 说明
- 左栏宽 156dp，选中项走强调色胶囊；**整栏只占一个焦点停靠点**：
  上下切分类、右键进内容——比让 5 个分类各自进焦点遍历更好预测
- 手机窄屏（内容宽度 < 620）自动折成顶部横滑胶囊，左右切分类、下键进内容
- 面板表面从 `Colors.black87` 换成 `AppColors.overlay` + 1px `stroke` 描边
  （方案 3.8 三件套第二件），在暗画面下能看出边界
- 内容页仍是"只构建当前页"，切分类不会把隐藏页的控件留在焦点树里

### 双域选台：左侧列表 电视 / 电台 ✅（方案 12.6）

左侧频道列表顶部两个胶囊签 `📺 电视 | 📻 电台`（带数量）：

- **电台域是跨源聚合**：`我的电台` 在前，其后是内置精选五个分组。
  切标签**不动当前节目源**，点哪个台播哪个台（`playChannel`），

- **收藏按域分流**：电视收藏、电台收藏各看各的，一列里不混两种东西。
- **遥控器**：第一级按左键切域（右键留给"进分类"），第二级左键回上一级。
- **记忆**：打开抽屉时跟随"正在播的那一类"切域，但只在频道变了时切——
  手动翻到电台后关掉再开，不会被拽回电视。

**12.6 剩余三项已补齐**：

- **电视伴音自动匹配**：拿当前电视源的频道名去电台源里找同名独立
  音频流（`RadioCatalog.withTvCompanion`），匹配到的才进「电视伴音」组，

  切源/刷新频道后重算。
- **菜单键一键切域**：左侧列表打开时菜单键在电视/电台间切换
  （此前该键空闲）。
- **双域独立记忆**：电视、电台各存一份上次频道，另存"上次所在域"；
  启动恢复「上次所在域 + 该域上次频道」。

### 播放态视觉（方案 12.3 第二档）✅

电台没有画面，最容易出的误会是"是不是没播"。三处同时给信号：

| 位置 | 元素 |
|---|---|
| 播放区 | 台标 → **25 根起伏波柱**（`AudioWave`）→ 台名 → 呼吸点 +「正在收听」+「音频流」小标 → 当前节目 |
| 底部面板 | 分辨率位换成「🎧 音频直播」徽章（4 根跳动小条），暂停时波柱压平、文案变「已暂停」；电台不显示「线路 x/y」这类无意义项 |
| 频道列表 | 圆形台标 + 电台分组，与电视同一套焦点/收藏 |

波形走**两级**，能真就真：

1. **真实波形（首选）**：电台起播前给 libmpv 设 `lavfi-complex`

   ```
   [aid1]asplit[ao][sp];[sp]showwaves=s=480x96:mode=cline:rate=25:colors=0xFFFFFF[vo]
   ```

   音频一路照常出声（`[ao]`），一路交给 ffmpeg 的 `showwaves` 画成波形
   并作为视频输出（`[vo]`）。mpv 因此产生真实视频帧，Flutter 侧拿
   `VideoController` 的纹理贴在台标下方——**跟着真实 PCM 起伏**，
   不需要自己抓音频做 FFT。滤镜链建不起来（mpv 未编 showwaves 等）
   会在 6 秒内报错，自动摘掉滤镜重开同一路流，退回第 2 级。

2. **缓动波形（兜底）**：`AudioWave` 自绘。每根柱独立相位/速度/包络，
   上升快回落慢（14:5 阻尼），起播从 0 涨起、暂停平滑收平后停表。
   只在 paint 阶段算高度，60fps 成本可忽略。

底部面板与「音频流」小标上的 3~4 根迷你条始终用第 2 级（几像素高，
没必要为它开一路纹理）。

## 五点十一、电台波形「不动」与按 UA 分流的源（11-13 下午）✅

### 1. 电台波形没起作用

原实现是两级：先让 mpv 用 `lavfi-complex` 把音频画成视频帧（`[vo]showwaves`）当纹理贴出来，
失败才回退 Flutter 缓动波形。实测这条路在纯音频 HLS 上经常**建不起来又不报错**——
`size` 有值但纹理是黑的/不刷新，看到的就只是"一块不动的黑底"，正好对上反馈。

改为**电平表驱动**，不再依赖 vo：

| 环节 | 做法 |
|---|---|
| 取数 | `af` 链尾挂 `astats=metadata=1:reset=1:measure_perchannel=none`，整条链打 label `omi_lv`，然后每 90ms 读 `af-metadata/omi_lv/lavfi.astats.Overall.RMS_level`（dBFS）。纯音频流也有真实电平，不需要 PCM、不需要 FFT |
| 映射 | `(dB + 58) / 58` 夹到 0~1；`-inf`/`nan` 记 0（静音）；明显变化才推，避免每 90ms 抖一次 |
| 驱动 | 独立 `ValueNotifier<double> audioLevel`，波形组件直接订阅——**不走 ChangeNotifier**，不会为一条波形重建整棵播放树 |
| 兜底 | 5 秒内一直读不到就把 `audioLevel` 置 -1，波形自动切回"按播放态模拟"（必定会动），并停表 |
| 纹理 | mpv showwaves 降级为设置项「电台真波形纹理（实验）」，**默认关**；开了才贴纹理，换台生效 |

### 2. `zb.php` 拿不到节目列表 —— 服务器按 UA 分流

查清了：这个地址**按 User-Agent 返 302 到不同地方**。

| 请求 UA | 结果 |
|---|---|
| `okhttp/*`（TVBox、影视仓等壳子） | 302 → `http://zb.33191.com/zhibo/iptv.txt`，**100KB 真直播源**（8 分组 / 110 频道：央视 28、卫视 21、地方 39、体育 6…） |
| 浏览器 UA / Dart / 空 UA | 302 → `http://nn666.shop/`（推广落地页，没有直播源） |

壳子能解析不是靠什么参数，就是它们的网络栈默认 UA 是 OkHttp。
我们请求本来就带 `okhttp/3.15`（v1.0.201 就有），所以链路本身是通的——
在沙箱用同 UA 抓下来丢给 `PlaylistParser`，实解 **8 分类 110 台**。

- UA 三级回退：`okhttp/3.15` → 浏览器 → `VLC/3.0.18`；拿到 HTML 也先留着当兜底
  （影视仓那类聚合分享页本来就是 HTML，不能判死），三档全挂才报错
- **源诊断**（设置 → 直播源 → 源行「诊断地址」）：用三种 UA 各跑一遍完整跳转链，
  列 HTTP 码 / 跳转次数与落点 / 字节数 / 是否 HTML / 解析出多少频道（带前三个台名）。
  UA 分流、跳广告页、编码错位一眼可辨，不用再猜

## 五点十四、五个实测问题（退出崩溃 / 假死 / 闪黑 / 电台无声）✅

用户在一台 Win10 家庭版 1607 上反馈四类问题，逐条定位如下。

### ① 退出仍弹「已停止工作」（0xc0000005）

根因是**两个窗口监听抢着退出**：`main.dart` 里为「✕ 最小化到托盘」
加的监听直接 `windowManager.destroy()`，而播放页里那套「先退出网页态 →
释放 WebView2 环境 → 快速退出」的顺序流程也在跑。谁先取决于注册顺序，
一旦 main 的先跑，WebView2 平台视图就随引擎一起拆，COM 释放与引擎关停
并发 → 崩溃回来。

修复：新增 `lib/services/exit_guard.dart` 作为唯一出口，所有退出入口
（标题栏 ✕、托盘「退出」、快捷键）都走它：

1. 播放页注册 `prepare`：退出网页态 → 等 600ms 让平台视图原生销毁 →
   主动释放 mpv 内核（`prepareForExit`）→ 释放 WebView2 环境
2. 通知 runner 摘低级键盘钩子、恢复光标（跳过会崩的析构链）
3. 再等 500ms，最后 `setPreventClose(false)` + `destroy()`

### ② 输入框之间快速点，卡住不响应

上一版规避 TSF 缺陷的做法是每个输入框 `onTap` 里先 `unfocus()`、
150ms 后无条件 `requestFocus()`。用户快速来回点时，A 的定时器把焦点
从 B 抢回来，两个框拉锯 → 同样表现为假死，而且更严重。

修复：改成**全局点击序号**。每次点击 `++_tapSeq`，延时回调只在
「自己仍是最新一次点击」且「期间没有别的控件拿到焦点」时才补挂；
已聚焦的框再点不再折腾。宁可少重建一次 IME，也绝不抢别的框焦点。

### ③ 设置页拨开关后假死 1–2 秒

`_saveSettings` 每次把 **25 个键全量写一遍**。Windows 上每个 `set` 都是
一次平台通道 + 整份 JSON 文件重写，且平台线程就是 UI 线程——一次拨开关
等于 25 次同步写盘，老机器上正好一两秒。

修复：改为差量写入。`SharedPreferences` 自带内存缓存，`get` 是同步且
便宜的，先比较再写，一次拨开关通常只落 1 个键。

### ④ 播放中开面板/滑节目单，画面闪黑一下

与 MPV 纹理的绘制方式有关：打开面板、OSD 淡入都会让上层 `Consumer`
重建，纹理 widget 跟着重建，Windows 上（尤其 1607 老显卡）会掉一帧黑。

修复两处：

- `_TextureSurface`：缓存 `vc.build()` 的结果，只有**内核实例变化**才
  重建纹理子树；外层再包 `RepaintBoundary`
- 播放页视频层整体加 `RepaintBoundary`：面板滑动、OSD 淡入只重绘自己
  那一层，不再带着视频纹理整屏重绘

### ⑤ 电台仍然没有声音（视频正常）

视频不挂音频滤镜、电台挂，差异就在 `af` 链。上一版为了让波形跟真实
响度走，给电台串了一条 `astats` 电平表；部分机器（1607 + 某些声卡）
挂上后整路无声。

修复：

- 新增设置「电台电平驱动波形（实验）」，**默认关**。关着时完全不碰
  音频链，波形按播放态动画（视觉上照样起伏）
- 开着时若 5.5 秒读不到电平数据，自动摘掉 `astats` 保住声音并把波形
  退回模拟（日志 `af-metadata 不可用，摘掉电平表`）

### 验证

- `flutter analyze lib`：无 error / warning（只剩既有 deprecated info）
- 时序相关的三条（退出、IME、闪黑）只能在真实 Windows 机器上验，
  沙箱无法模拟 WebView2/TSF/D3D

### 构建侧：安卓红叉的真正原因（run 43346824553 日志）

`8ce550c` 的 Windows 作业成功（`windows-build 43.4MB`），安卓作业在
562 秒处报 `The runner has received a shutdown signal`、Gradle exit 143。
查日志确认不是编译错误——是免费 runner 在 9~10 分钟处被回收。

原因是 `--split-per-abi` 编 4 个 ABI（arm64 / arm / x86_64 / x86），
mpv 原生库每个 ABI 都要单跑一遍 NDK + CMake，把作业从 ~6 分钟拖到 10
分钟以上，正好卡在回收窗口里。此前 #49/#50 的红叉也是同一原因。

修法（`.github/workflows/build.yml`）：

1. `--target-platform android-arm64,android-arm`：只编两个真机 ABI，
   x86_64 只有模拟器需要，直接砍掉，作业时间减半
2. 加 `actions/cache` 缓存 `~/.gradle`：NDK/CMake 与 mpv 的 jar 复用
3. 构建加一次自动重试（`for attempt in 1 2`）：缓存已热时重试只需
   两三分钟，硬扛一次 runner 抽风

## 五点十七、MDK 录制/截图补全（11-13 中午）✅

   `PlayerController` 侧「当前内核不支持录制」的拦截是按返回值判断的，
   自动放行
2. **截图**：原来 `snapshotPng` 把 RGBA 裸数据直接当 PNG 落盘——MDK 下
   截出来的文件其实是坏的。现在按 OMPlayer 同款做法：RGBA →
   `ui.ImageDescriptor.raw` → 解码 → `toByteData(png)`，先转码再落盘
3. **音频**：按用户决定放弃 MDK 下的均衡器/EQ（`af` 滤镜链是 libmpv
   独有，MDK 没有）；真电平波形同样不碰（astats 在部分机器上整路无声），
   波形维持播放态驱动的动画。设置页文案已写明差异

### 关于「别家的波形是不是真的」

网页端（WebAudio 的 `AnalyserNode`）能直接分析 `<audio>` 的 PCM，所以
Last.fm、listen.moe 这类网页播放器给的是真频谱；桌面播放器（mpv/fvp）
拿不到解码后的 PCM——要么挂音频滤镜（我们实测部分机器整路无声），要么
做系统级混音采集（复杂、还会把系统其它声音一起采进来）。所以桌面端的
"波形"基本都是播放状态驱动的模拟动画，这不是我们偷懒。后续如果想升级，
可以只在网页电台走真频谱、桌面保持动画。

### 验证

`flutter analyze`：0 error / 0 warning。录制/截图路径与 MPV 共用同一套
`OmiVideoBackend` 接口，无需 UI 改动。

## 五点二十、投屏画面「加速 / 跳帧」——MDK 开了 live 低延迟档（11-13 傍晚）✅

### 现象

默认内核改 MDK（v2.0.1）后，DLNA 投屏播放**画面像在快进**：进度条飞、
帧跳着走、音画对不上。同一台机器：昨晚版本（默认 MPV）投屏正常；用户
原来的 OMPlayer（也是 MDK）投屏也正常。

### 根因

投屏复用 `playChannel()`，内核按 `settings.playEngine` 走 MDK。而
`omi_video_mdk.dart` 注册 fvp 时抄了「直播低延迟」的写法：

```dart
fvp.registerWith(options: {
  'lowLatency': 2,           // ← 元凶
  'video.decoders': ['MFT:d3d=11', 'D3D11', 'DXVA', 'auto'],
});
```

fvp 对 `lowLatency >= 2` 的每个播放器会做三件事（见 `video_player_mdk.dart`）：

- `avformat.fflags = +nobuffer`（丢第一个关键帧）
- `avformat.fpsprobesize = 0` + `analyzeduration = 100000`
  —— **不额外探测帧率，直接信容器头**，帧率估错就按错误速度出帧
- `setBufferRange(min: 0, max: 1000, drop: true)`
  —— **只留 1 秒缓存，解码跟不上就丢帧追最新**

直播（追最新）正合适；投屏点播（视频号 mp4、腾讯视频 HLS 点播）就变成
「丢帧赶进度 → 画面加速」。OMPlayer 的 MDK 注册用的是
`player.buffer.range` + avio 重连，**从不碰帧率探测**，所以它投屏正常。

### 修复

`_register(bufferSeconds)` 改为 OMPlayer 同款：

- 去掉 `lowLatency`（不再设 nobuffer / fpsprobesize / drop）
- `player.buffer.range = "起播预读+上限"`（max = 用户缓冲设置，投屏点播
  取 15 秒、HLS 最高 10 秒；起播预读最多 3 秒）
- 补 avio 断线重连（reconnect / reconnect_streamed / rw_timeout 15s）
- 解码器列表加 `CUDA / hap / FFmpeg / dav1d` 软解兜底（原来只到 'auto'，
  老显卡硬解失败时容易直接报错）
- 缓冲秒数变化时重新注册（fvp 的玩家级选项对之后创建的实例生效）

### 验证

`flutter analyze lib/services/media/omi_video_mdk.dart`：0 error / 0 warning。
用户侧验证：投屏播放速度应恢复正常，拖进度、暂停/继续、抖动重连与 MPV
一致。

## 五点二十一、投屏中扫不到设备 + 安卓电台通知卡不显示（11-13 傍晚）✅

### ① 已投屏状态下，想再投一条却扫不到设备

现象：已经投上，接收端没断开；此时在手机里再打开投屏面板，列表里刷不出
「欧米视听」；回接收端点「断开」后立刻又能扫到。

SSDP 侧逐项核对：M-SEARCH 应答不依赖投屏状态、设备名固定、1900 组播组
一直在线。差异在**丢包**：断开时 `kickCastClients()` 会 byebye + 立刻
补一轮 alive（一次突发 6 条），而常规周期通告是 **10 秒一次**——投屏中
CDN 大流量占满热点网卡的 UDP 小队列，M-SEARCH 的单播应答与周期 alive
都容易丢，表现就是「这一下没扫到」，断开时那波突发刚好撞上。

加固：

- `_respondSearch` 改为**两轮应答**（100ms / 600ms）：发送端按 USN 去重，
  不会重复出现设备，只是多给一次命中机会
- alive 周期 10 秒 → **5 秒**（6 个小包，开销可忽略）

### ② 安卓电台没有通知栏 / 锁屏卡片

查了三层，两个真问题：

1. **`MediaService` 没在 AndroidManifest 里注册**（v2.0.4 的漏项）。没注册
   的服务 `startForegroundService` 直接抛 "not found"，而 Dart 侧
   `audioNotify` 吞异常 → 卡片永远出不来。CI 里补 `<service>` 声明，
   `foregroundServiceType="mediaPlayback"`，并加 grep 校验防漏
2. **Android 13+ 没申请 `POST_NOTIFICATIONS`**。清单里声明了权限，但从未
   运行时请求；系统默认拒绝 → 前台服务照跑，通知被吞（锁屏也没有控件）。
   新增原生 `requestNotif` → `requestPermissions`，Dart 在首次进入电台时
   申请一次（`_ensureNotifPermission`，`_notifAsked` 防重复弹窗）
3. 顺带把 `MediaService.update()` 的 `startForegroundService` 包 try/catch：
   Android 12+ 后台起前台服务会抛 `ForegroundServiceStartNotAllowedException`，
   不能让它连累播放

## 五点二十二、定时关闭三档动作 + 固定时刻 + 网页远程设定（11-13 晚）✅

### 背景

原来的定时关闭（方案 12.4）只有「30/60/90 分钟 + 到点暂停」，动作写死在
会话里。用户实测后提了三点：① 电视/电影看完睡着，希望到点直接退程序；
② Windows 上更希望「退出并关机」，不用起来关电脑；③ 分档倒计时不够，
想按「晚上 11 点半」这种固定时刻；④ 这些选项在设置面板和手机扫码页
（Web 管理）里也应该能改。

### 改动

**① 到点动作从两档扩到三档**

```dart
enum SleepAction { pause, exit, shutdown }
```

- `pause` 暂停播放、留画面；`exit` 退出程序；`shutdown` 退出并关机
- `shutdown` 仅桌面端出现（移动端应用无权关机，`setSleepAt` 里自动降级
  成 `exit`，不会出现"选了却不生效"）
- 动作与目标时刻写进 `PlayerSettings`（`sleepActionKey` / `sleepAtMs`），
  跨启动记住；重启后若目标时刻仍在未来则自动续上，已过期则清掉不补触发

**② 关机顺序：先发系统命令，再退程序**

```dart
await shutdownSystem(delaySeconds: 15);  // shutdown /s /t 15 /f
await ExitGuard.quit();
```

反过来的话 `ExitGuard` 结束后进程先没了，关机命令可能发不出去。给 15 秒
缓冲：Linux 用 `shutdown -h +0`，Windows 上用户还能在终端 `shutdown /a`
撤销。到点前先 `flushSettings()`，把 `sleepAtMs = 0` 落盘——不然重启后
会按旧时刻再触发一次。

**③ 固定时刻（最近一次）**

`setSleepAt()` 统一入口，倒计时也走它（`setSleepTimer` 薄封装）。界面上
给 22:00 / 22:30 / 23:00 / 23:30 / 00:00 五档 + 「自定义…」调系统时间
选择器；语义是**最近一次**：现在 22:10 选 23:30 是今晚，凌晨 1 点选 23:30
是明晚，不会天天循环触发（避免「设了一次，天天被关机」）。

**④ 三处入口共用一套 UI**

- 新建 `lib/widgets/sleep_timer_dialog.dart`：动作 chip + 倒计时 chip +
  固定时刻 chip + 取消
- 底部面板「定时关闭」按钮 → 该弹窗（原来的独立实现删除）
- 设置 → 系统设置 → 新增「定时关闭」一行，副标题实时显示
  「23:30 退出并关机 · 还剩 2 小时 14 分」
- Web 管理页（手机扫码）→「设置」tab 新增定时关闭卡片：动作 / 倒计时 /
  固定时刻 / 自定义（`prompt` 输 HH:MM，兼容旧 X5 内核）/ 取消

Web 通道复用 `settings` 快照：`sleepActionKey` / `sleepAtMs` 随
`/api/snapshot` 下发与回写；`applySnapshot` 里先落动作再按毫秒值重装
定时器（顺序反了会被默认动作覆盖）。

**⑤ 入口从「底部面板」收进「退出卡片」（用户反馈后调整）**

第一版把定时关闭放在底部控制面板，紧跟在电台录音后面，看起来像电台专属
功能。实际上它和「退出 / 关机」是同一类操作，且本来就与频道类型无关
（`_runSleepAction` 只碰 `togglePlayPause` / `ExitGuard` / `shutdownSystem`，
不看 `isRadio`）。调整：

- 退出卡片新增一格「定时关闭」（bedtime 图标，颜色 `deepPurpleAccent`），
  位置在「设置」和「退出」之间；已设定时标签直接显示剩余（`2:14` / `45 分`），
  未设定显示「定时关闭」
- 点击后先 pop 卡片再弹 `showSleepTimerDialog`，与设置面板、手机网页
  共用同一套 UI 与状态
- 底部面板那个按钮移除（`_KbAction('sleep')`、`sleepRemain`、`_fmtRemain`
  一并删掉，`bottom_program_panel.dart` 不再依赖 sleep 模块）
- 退出卡片宽度改成按项数算：`n*48 + (n-1)*16 + 56`，`clamp(340, 640)`；
  项齐时 8 格（返回/锁定/小窗/扫码/设置/定时/退出/关机），原来固定 500
  会把图标和标题整体缩一圈
