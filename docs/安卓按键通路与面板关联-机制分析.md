# 安卓按键通路与「面板关联」症状 — 机制对照分析

> 原则（用户定）：Windows 侧 2.1.37 已验证逻辑**一律不动**；修安卓先捋清机制再动手，不套用 Windows 补丁、不瞎猜乱改。Windows 的坑已经踩过一遍，安卓逐条对照，先诊断后开方。

## 一、两个平台的按键通路对照

| 环节 | Windows（已验证好） | Android（待修对象） |
|---|---|---|
| 遥控器按键 → Flutter | Android 系统层无钩子；按键经系统 KeyEvent → Flutter Engine → `HardwareKeyboard` | Android 系统分发 KeyEvent → Flutter Engine → `HardwareKeyboard`（同一入口） |
| 网页态播放页 | `webview_windows`（WebView2）：**焦点被 WebView2 抢走，`HardwareKeyboard` 完全收不到键** → 只能靠 Windows 低级钩子（`WinHotkeys`）吞键转发 `_onNativeAction` | `flutter_inappwebview`（InAppWebView）：WebView 持有焦点时按键被 Android WebView 消费，**同样到不了 `HardwareKeyboard`**——症状与 Windows 同源，但**没有钩子这条救命通道** |
| 返回键 | `k:back`（钩子）+ Esc（JS 桥转发）→ `_handleBackPressed('native')` | 系统返回手势/按键 → `PopScope`（`src=pop`）→ `_handleBackPressed`；网页态下系统返回可能被 WebView 自己消化（网页历史后退），到不了 PopScope |
| 输入法 | 中文输入法下硬件 KeyDown 照样送达 `HardwareKeyboard`（已验证） | 软键盘按键走 **TextInput/IME 通道**，根本不进 `HardwareKeyboard`——这是当时「输入法误诊」在安卓上的真实差异点，不能再往这上面猜 |
| 原生层 | 注入 win_hotkeys 低级钩子 | CI 里 `flutter create` 生成，**零自定义 Kotlin**，没有任何原生转发能力 |

## 二、Windows 踩过的坑 → 安卓对照表

| Windows 症状 | Windows 真因（已验证） | 安卓预期表现 | 安卓对策方向（未动手，先诊断） |
|---|---|---|---|
| 设置面板/卡片打开时 OK/返回失灵，关掉又好 | **面板状态与按键通路的关联**：面板打开时按键被面板消费，面板销毁后通路没归还/状态位没复位 | 同一关联在安卓上表现为：面板/卡片开关后遥控器某一组键僵死 | 先复现：开/关设置面板 → 逐键测试并记录哪组键、哪个状态下失灵；在 `_resetKeyPairing`/面板开关路径加 WebDiag 日志取证 |
| 网页态 OK 全失灵 | WebView2 抢焦点 + 钩子 fg_ok 误判（g_om_web_forward 修复） | InAppWebView 抢焦点，Flutter 收不到 OK 键 | **安卓无钩子**。可行通路：InAppWebView 的按键拦截回调（`shouldOverrideKeyHandling` / 原生 `dispatchKeyEvent` 桥）或 JS 层监听 + JS 桥转发 `_onNativeAction`（与 Windows 的 JS Esc 转发同思路） |
| 返回键能调退出菜单但退不出去 | 多通道重复投递/吞键（`_lastLayerCloseAt` 去重闸门已处理） | 系统返回被 WebView 吃掉做「网页后退」， PopScope 收不到 | 验证 InAppWebView `canGoBack`/返回拦截配置；确认 PopScope 是否收到事件 |
| 左边缘热区不弹面板 | （2.1.37 本来就好，加宽是无效动作，已回退） | 待验证安卓是否有同样现象 | 不预防性改动；只在用户报了之后再对症状取证 |
| 时间戳自愈、键值上报堆补丁 | 错误方向，全部回退 | —— | 安卓侧禁止再走「不对比先打补丁」的路 |

## 三、安卓侧纪律（照 Windows 的教训立规矩）

1. **先取证再改码**：每一步改动前，先在真机上复现症状 → WebDiag/日志记下「哪个键、哪个面板状态下、走了哪条通道」→ 与正常状态对比，找到确切的失联点。
2. **每次只动一个变量**：改完即出测试包（Actions artifact）→ 真机验证 → 通过才进下一项，不攒改动。
3. **Windows 文件隔离**：`win_hotkeys.dart`、`build.yml` 的 Windows 钩子段、player_screen 里 `TargetPlatform.windows` 分支——修安卓时一律不碰。安卓改动只落在 `TargetPlatform.android` 分支或新文件里。
4. **不复用 Windows 补丁**：`vk:XX` 兜底、`g_om_hidden`、fg_ok 这些是 Windows 特有机制的产物，安卓症状即使「像」，也要按安卓通路重新诊断，不直接照搬。
5. **改动前后 diff 对比基线**：任何安卓侧改动，diff 范围必须能逐行说清「改了什么、为什么、对应哪个取证结论」，说不清就不提交。
