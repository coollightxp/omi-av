# 欧米视听（原欧米直播）界面与体验改造方案

> 项目名定稿：**欧米视听**（英文品牌 **Omi**，仓库 `omi-av`，包名 `cn.omi.av`）——保留"欧米/Omni"血统，"视听"覆盖看+听+投全部场景，规避"直播"字样的审查风险；英文不用 OmniTV（Google Play 已有同名应用）与 OmniVision（撞豪威科技商标）。
> 基于现有 Flutter 项目（media_kit 直连流 + WebView 央视频兜底 + DLNA 投屏接收）的全量改造清单。
> 设计哲学：仿酷9 / TVBox 的简洁直观——频道逻辑而非点播逻辑，功能都在，但日常视野里不打扰。

---

## 一、总体设计原则

1. **打开即在播**：启动直接全屏播放上次频道（可在设置关闭，关闭时进入"待选台"画面），面板都是临时覆盖层，自动隐藏
2. **输入方式决定按钮存废**：电视=纯遥控器、Windows=键鼠双轨、手机=触摸
3. **字号是一切尺寸的源头**：字号 token 驱动按钮、行高、面板高度全链路
4. **短按管播放、长按管深度**：界面极简，深度功能藏在长按和退出卡片
5. **布局系统成套**：三端统一等宽停靠面板，左右通高 + 底部等宽，围成框架

## 二、架构层改造（第一优先级）

### 2.1 焦点协调器（根治"焦点穿透"）

- 全 App 唯一焦点状态持有者：`FocusRegion` 枚举（player / channelList / epg / bottomPanel / exitCard / numberInput）
- **所有硬件按键统一进协调器分发**，按当前 region 派给唯一处理者，处理过返回 `handled`，杜绝按键冒泡穿透（面板和播放器同时响应的 bug）
- 面板打开时**存档当前焦点**，关闭时**恢复原焦点**（从第 37 个频道打开 EPG，关闭后回第 37 个）
- 封装 `safeRequestFocus()`（内部包 addPostFrameCallback），根治对未挂载节点调用静默失败的问题
- 面板打开瞬间，播放器区按键监听挂起（双保险）
- **迁移方式**：逐面板接入，接一个删一个旧补丁；顺序：频道列表 → EPG → 底部面板 → 退出卡片 → 数字输入；任何时刻项目可编译可运行
- **验收**：快速随机开关面板 20 次，任何时刻方向键恰好触发一个动作

### 2.2 播放能力层解耦

```
lib/player/
├── player_service.dart      # 统一接口：play/pause/switchSource/qualityLabel
├── media_kit_player.dart    # m3u8 直连流实现
├── webview_player.dart      # 央视频 WebView 兜底实现
└── cast_receiver.dart       # DLNA 投屏接收（独立 service，不与播放器耦合）
```

- 界面只调接口，不感知底层是 media_kit 还是 WebView
- **`qualityLabel` 统一字段**：UI 只读这一个字段
  - 直连流：从视频轨实时读（`tracks.video` 宽高换算），监听轨道变化（HLS 自适应切档要刷新）
  - 央视频源：源即分辨率，切源时从元数据写入

### 2.3 播放哨兵与分级重载

| 内核 | 卡死检测 |
|---|---|
| 直连流 | 播放位置 3 秒不动 + 状态 playing = 卡死 |
| WebView | 路一：注入 JS 轮询 `currentTime`，两次不动且非暂停 = 卡死；路二（兜底）：帧比对，连续 2-3 帧相同 = 卡死 |

- **分级重载**：软重载（JS 令页面播放器重连，1-2 秒）→ 硬重载（整页刷新，5-10 秒）
- 重载 N 次失败 → 面板显示"该线路暂时不可用 [重试] [换线路]"，不无限重试
- **手动重载按钮永久保留**（广告页/登录墙/内容不对等只有用户能判断的情况），点击自动先软后硬

## 三、底部面板（改动核心）

### 3.1 布局形态

- **三端统一等宽停靠**（手机端从浮动卡片改回等宽，回收两侧留白）
- 半透明底，**顶缘渐变**（透明 → 面板底色，16-24px），面板"从画面里长出来"
- 底色、圆角与左右面板用**同一个 token**

### 3.2 信息区（左侧，只读）

- 台标用深色容器（同面板色系），不做白色底块
- 两行结构：`频道名（加粗）+ 画质 chip` / `正在播节目 · 时间段`
- 手机端砍掉技术信息行（硬解/码率），只留频道名 + 节目

### 3.3 按钮清单（最终版，无"更多"）

| 平台 | 按钮（从左到右） |
|---|---|
| **Windows** | ‹ 线路 2/6 › ┃ ❚❚ 🔇 ┃ ↻重载 ┃ ⛶全屏 ⧉小窗 ⟳旋转 ┃ 📷 ⏺ |
| **安卓** | ‹ 线路 2/6 ›  ❚❚ 🔇  ↻重载  ⟳旋转 |

- 分组竖线（仅 Windows）：1px 宽、高 16-20px（短于按钮）、白色 12-15% 透明度、两侧留白 12-14px；**手机端不画线，纯间距分组**（组内 8px、组间 28px）
- **统一 ghost 按钮组件**：同高度、同圆角、统一图标线宽；播放/暂停最大且用主题色；静音图标随状态切换；全屏钮反映当前状态
- Windows 端按钮悬停 tooltip 显示快捷键（如"暂停 (空格)"）
- **"更多"按钮取消**（功能要么在面板要么在退出卡片，无空层）；将来加音轨/字幕切换时再回归
- 设置按钮**不放面板**，家在退出卡片

### 3.4 换源步进器

- `‹ 线路 2/6 ›`：尖括号（上一项/下一项语义，不用 ⏮⏭ 快进图标）
- 点中间 chip 弹出**线路菜单**：宽约 240px、锚定 chip 正上方、每行标实际画质（写人话："1080P 超清"，不用"源 N"）、当前项打勾、面板高度不变
- 遥控器左右键直接切换，鼠标点 chip 弹菜单选择

### 3.5 尺寸规格（密度 token）

| 设备 | 面板总高 | 按钮直径 | 字号（标题/正文） |
|---|---|---|---|
| 电视 | 76-80dp | 44dp | 18sp / 15sp |
| Windows | 64-68dp | 38dp | 15sp / 13sp |
| 手机横屏 | **≤56dp** | 34-36dp | 13sp / 10.5sp |

- **验收**：手机横屏面板高度 ≤ 屏高 1/6

### 3.6 投屏态模板（同一组件，第二份配置）

- 信息区切换为：`正在投屏 · 设备名`
- 隐藏换台/换源/EPG（内容由投屏方决定）；保留 ❚❚ 🔇 ⟳ + **断开投屏**（投屏态下常驻）
- 投屏结束后的去向由设置控制（五档）：**马上返回 / 等待 1 分钟 / 5 分钟 / 10 分钟 / 一直等待**

### 3.7 投屏等待画面

- 检测到投屏流结束后（且设置不是"马上返回"）进入等待态：全屏深色画面 + 居中提示 `正在等待投屏`
- 底部小字常驻操作提示：`双击返回键 返回直播`
- **双击返回判定**：两次返回键间隔 ≤ 2 秒即返回原频道（单击只短暂提示，不退出，防误触）
- 档位计时到点自动返回原频道；"一直等待"则驻留，期间投屏接收服务持续监听，新投屏进来直接开播
- 等待画面极简（一个图标 + 两行字），不显示任何播放控件

### 3.8 表面层级与面板边界（暗画面下的可见性）

问题：待机/等待等暗画面下，暗色面板与背景融为一体，弹出后看不到边界。

修法三件套（所有弹层通用）：

1. **面板出现时背景压暗**：任何面板/弹层弹出时，画面叠一层 25-30% 黑色 scrim（淡入 200ms）——面板永远坐在比它暗的底上，边界天然成立
2. **面板亮两阶 + 1px 亮描边**：面板表面色比基底亮两阶（表面层级 token：base → surface → overlay），描边白色 ~15% 透明度；投影柔和（大半径低透明度，不用重阴影）
3. **弹层再高一级**：退出卡片、设置中心等模态弹层用 overlay 色 + 更强描边，与常驻面板再拉开一层

> 这三件全进 token 体系（`surface` / `overlay` / `stroke` / `scrim`），不是零散写死的样式。

## 四、弹层体系

| 弹层 | 内容 | 触发 |
|---|---|---|
| **退出卡片** | 返回 · 锁定 · 小窗(Win) · 扫码 · 设置 · 退出 · 关机(Win) | 返回键 |
| **线路菜单** | 各线路画质列表 | 点换源 chip |
| **EPG 右面板** | 节目单 + 预约 | 菜单键短按 |

- 弹层壳（圆角/底色/焦点发光/D-pad 导航）统一为一个组件复用
- 设置/Web 服务/锁定/关机全部收在退出卡片，主面板不放
- Web 服务在设置页显示状态行（"运行中 192.168.1.5:8080"），不加按钮

### 4.1 设置页重设计（顶部四 Tab → 双栏设置中心）

现状：底部弹出卡片，顶部"节目源 / EPG / 系统设置 / 说明"四个 Tab，观感旧、宽屏上散。

改法：**左侧竖向分类栏 + 右侧内容区**的现代双栏结构：

- **左栏（窄，约 150dp）**：四个分类项（图标 + 文字），当前项高亮胶囊；D-pad 上下直接切分类，左栏到右栏用左右键，焦点路径清晰
- **右栏**：设置项列表行——每行 = 标题 + 副标题说明 + 右侧控件（开关 / 下拉值 / 滑块），行间细分隔线
- **手机窄屏适配**：左分类栏折叠为顶部横滑胶囊分段（segmented chips），其余不变
- 视觉走 3.8 节表面层级（overlay 层），与底部弹出的卡片壳一致
- 已定稿的设置项（启动恢复频道、设备模式、投屏结束五档、字号滑块等）都落在这个新结构里

## 六、密度与字号体系

### 6.1 三档设计 token（自动按设备取档）

| 语义 | 电视 | 桌面 | 手机横屏 |
|---|---|---|---|
| 标题 | 18sp | 15sp | 13sp |
| 正文 | 15sp | 13sp | 10.5sp |
| 列表行高 | 60-64dp | 48-52dp | 40-42dp |
| 面板高 | 76-80dp | 64-68dp | ≤56dp |
| 分组竖线 | 有 | 有 | **无（纯间距）** |

- 组件内禁止写死字号/间距，全部取 token
- **验收**：手机横屏频道列表一屏 ≥10 个频道；面板 ≤ 屏高 1/6

### 6.2 用户字号滑块（第二层，叠加在自动档之上）

- 范围 **0.85x – 1.30x**（超出布局会散架），实现用 `TextScaler.linear`
- **行高必须随缩放系数联动**，不可写死（滑块最大翻车点）
- TV 端步长 0.1（遥控器好按）、调整实时预览、附"恢复默认"
- 定位：自动档解决设备差异，滑块解决个体差异（老人看电视需要大字）

## 七、平台差异汇总

| 功能 | Windows | 安卓 |
|---|---|---|
| 截屏 / 录屏 / 关机 | ✅ 仅此端 | ❌ |
| 小窗（迷你模式） | ✅ 仅此端 | 改为**切后台自动浮窗**（设置可关；正常退出不浮窗；浮窗带 暂停/关闭/回主程序） |
| 旋转 | ✅（竖屏显示器场景） | ✅（竖屏投屏内容场景） |
| 投屏 | 后台服务无按钮，投屏中断开入口 | 同左 |
| WebView 央视频 | 兜底，独立页面式 | 兜底，独立页面式 |

### 安卓双模式开关（设置项：设备模式 = 自动 / 手机平板 / 电视）

- **为什么需要**：同一 APK 跑在手机和盒子上，系统类型检测不可靠（无触摸盒子、刷机设备等），手动开关兜底
- **自动档判定**：`uiMode == television` 或无触摸屏 → 电视；否则手机平板
- **电视模式**：密度取电视档（大字号大按钮）、焦点导航优先、**小窗/浮窗功能隐藏**（盒子无意义）、EPG/列表按 D-pad 优化
- **手机平板模式**：密度取手机档、触摸手势可用、切后台自动浮窗可用
- Windows 不出现此设置项
- 实现：`DeviceProfile` 枚举（auto/phone/tv）存设置，密度 token 和平台按钮列表都从 profile 取值而非直接看平台

## 九、启动行为设置（新增）

设置项：**启动时恢复上次频道**（默认开）

| 状态 | 启动行为 |
|---|---|
| 开（默认） | 直接播放上次退出时的频道（现状逻辑，保留） |
| 关 | 进入**待选台画面**：深色全屏 + 居中提示（台标 logo + "请选择频道"），不发起任何网络请求；按 OK / 任意方向键 / 点屏幕 → 直接呼出频道列表 |

- 待选台画面复用投屏等待画面同一套"深色待机壳"组件，只是文案和响应动作不同
- 配套细节：关闭时"上次频道"仍然记录，只是不自动播；一旦用户选台，之后的自动重载/记忆逻辑照常

## 十、设置页卡顿排查（新增，需代码到手定位）

现象：设置里开关切换或其他操作时出现卡顿。候选原因按可能性排查：

1. **全局重建**：开关 setState 通知到了根 Widget，导致整个 App（含播放器层）跟着 rebuild —— 最常见
2. **同步 IO 在主线程**：设置持久化用了同步文件写，或 build 里读文件/解析频道列表
3. **ThemeData 重复生成**：每次开关触发主题重新计算而没有缓存
4. **视频 Surface 重建**：开关改变 MediaQuery/TextScaler 引擎层导致视频渲染面重建（表现为画面闪黑一下）
5. **SharedPreferences 异步未 await 引发的连环 setState**
6. 安卓端硬解与 UI 合成竞争（profile 模式下看帧率区分是逻辑卡还是渲染卡）

> 定位方法：代码到手后用 `flutter run --profile` + DevTools Timeline 看开关切换时的 rebuild 范围和耗时帧，先量再改，不猜。

## 十二、音频模式：听电视 / 听电台（新增）

### 12.1 本地桥：砍掉（定稿）

> 结论：不再实现 localhost 音频提取桥。原双通道方案（独立音频流优先 + 桥保底）简化为**单通道**：电台域只播真实的独立音频流。

- **理由**：桥是常驻本地 HTTP 服务 + m3u8 实时改写，是音频方案里最易出诡异 bug 的子系统；而社区伴音流已覆盖绝大多数想"听"的频道。为少数无伴音流的频道养一个高危子系统不划算
- **代价（知情取舍）**：无独立音频流的电视频道"只能看不能听"，不再有桥保底
- **桥原有附带能力不丢失**：UA/Referer 改写由 media_kit 播放参数（http-header）直接承担；"不渲染视频"由播放器 `--vid=no` 兜底（伴音频道天然全音频，基本用不到）
- **两个模式由频道类型决定，用户零选择**：
  - `📺 电视域 → 视频模式`：正常播放；安卓切后台 = 自动悬浮小窗（设置有总开关）
  - `📻 电台域 → 音频模式`：Now Playing 播放页；切后台/锁屏 = 通知栏媒体控制，照常换台

### 12.2 电台支持

- 频道类型扩展 `channelType: tv | radio`；电台源（HLS / Icecast / 直链音频）media_kit 原生可播
- **电台源机制 = 与电视源共用同一入口，设置页零新增项**（定稿，参照 LX-FM 三层混合且无独立"添加电台源"入口）：
  1. **内置精选**：出厂自带一份中国区电台精选作为"内置源"（源列表里一条，带类型徽标，可整体停用，支持远程更新）；可选一键导入 famelack 中国区 1,594 台进本地库
  2. **用户添加**：现有"添加源"入口原样共用——m3u 解析自动识别音频条目（`radio` 属性 / 音频后缀 / 无视频轨探测）标记 `channelType: radio` 进电台域；单文件内电视、电台混排均可
  3. **在线目录**：Radio Browser 搜索导入为源管理页内的功能按钮，不在设置页常驻
  - 源列表每条加类型徽标（电视/电台/混合/内置），纯显示
- **EPG 完全不动**：电台以 ICY 元数据为"节目单"；XMLTV 若含电台频道按频道号自动匹配，匹配不上不影响
- **正在播信息**：Icecast/ICY 元数据（`icy-title`，mpv 可读）显示当前曲目/节目；XMLTV 里带电台频道时同样显示节目表
- 电台列表进频道面板，分组可设"电台"组；数字跳台、上下换台、收藏逻辑与电视完全复用
- **台标三级策略（电台/电视通用）**：① m3u 内 `tvg-logo`/`radio-logo` 字段 ② Radio Browser 按台名补 favicon（缓存本地）③ 兜底自动生成"深蓝底+白色首字"字母台标，列表永不空白；"电视伴音"组台标直接继承电视域

### 12.3 电台增强（借鉴 LX-FM，已拆包分析验证）

> 参照物：LX-FM v1.3.7（Gitee 开源，Kotlin+Compose 原生安卓）。其源策略与本方案一致（Radio Browser + 国内精选直连流 + 自定义），差异化能力按性价比吸收：

**第一档（低成本，直接并入）：**
- **电台录音库**：边听边录、录音管理页、分享；流内直接抓取不转码，与 Windows 录屏能力同族
- **电台黑名单 + 换台自动跳过**：屏蔽指定电台/关键词标签，上下键换台时**不停留直接跳过**（与换台防抖联动）
- **场景制收藏**：收藏从单列表升级为多场景分组（新闻/音乐/戏曲…），电视频道同样适用；场景间一键切换
- 电台别名（个性化显示名）、睡眠定时（自定义时长）、导入时按标签/分类过滤

**第二档（中成本，反超点）：**
- **电台实时字幕**：sherpa-onnx 端侧流式 ASR（有官方 Flutter 插件，中英模型可选）——播放页实时显示播音内容；**电视大屏看广播字幕**是手机端做不到的体验，模型可下载可删
- **声音实验室**：均衡器 + 人声增强，走 mpv audio filter（firequalizer 等），挂 PlayerService 后即可

**第三档（不跟进）：**
- 听歌识曲：Shazam 无官方移动端 Flutter SDK，LX-FM 的 JNI 接入属非官方逆向，有失效与合规风险

### 12.4 电台播放页（Now Playing）

- 全屏深色画面：台标（大图 + 光晕）、台名、`正在播：节目/曲目 · 时间段`、下一档预告、码率/仅音频状态 chips
- **波形可视化：用 mpv 的 lavfi 音频滤镜（showwaves/showcqt）在视频纹理里渲染真实 FFT 频谱**——波形随真实音频起伏，全平台可用、零额外 PCM 采集代码；低端盒子性能不足时降级为缓动假波形动画
- 底部控制：上一台 / 播放暂停 / 下一台 / 静音 / 定时关闭 / **切回视频**（一键回视频模式）
- 待选台、投屏等待画面同一待机壳，风格统一

### 12.5 后台播放 + 通知栏/锁屏媒体控制

- **安卓**：`audio_service` 前台服务——通知栏 + 锁屏显示：台标做封面（media metadata artwork）、台名、正在播节目、**上一台/下一台/播放暂停**自定义按钮；切后台、锁屏不断播
- **Windows**：接入 SMTC（系统媒体传输控件），系统音量浮层/媒体键显示台名并可切台
- **电视/盒子**：息屏听电视（保持前台服务），遥控器照常换台
- 音频模式（电台域）天然全音频；"听电视" = 在电台域播放有伴音流的电视频道，同一套后台服务
- 前提权限：安卓 FOREGROUND_SERVICE / POST_NOTIFICATIONS（13+），随包配置

### 12.6 双域选台结构（电视 / 电台如何共存）

- **核心原则：域 = 一级开关，不是又一个分组。** 电视、电台是两个"世界"，各自有完整的分组树，互不混排。
- **电视伴音单通道（桥已砍，12.1）**：电台域只播真实的独立音频流（社区源自带的伴音条目，天然低码率省流量）。"听电视"概念消亡——在电台域听有伴音流的电视台即可

- **列表顶部两个胶囊域签**：`📺 电视 | 📻 电台`；焦点在列表第一行按"上"跳到域签行，左右键切域，↓ 回分组树
- **一键切域**：列表打开时按"菜单键"= 直接在电视/电台域间切换（菜单键在列表关闭时呼出 EPG、长按是外部设置，此状态下空闲正好利用）
- **电台域的分组**：
  1. **电视伴音**（第一组，自动匹配生成）：拿电视频道名/别名去**已导入的电台源里匹配同名独立音频流，匹配到的才进组**（继承电视域台标）；找不到的自然不出现。电视源或电台源更新后重新匹配一次
  2. **国家台**（央广/国广）
  3. **省市台**（地方电台）
  4. **网络电台 / 音乐**（可自定义）
- **列表行第二行按域取信息**：电台行显示 ICY 当前曲目；电视伴音行显示对应电视频道的 EPG 节目
- **换台边界**：上下键换台、左右键换源都只在当前域内循环——不会看电视换台"换进电台里去"
- **数字跳台分域**：电视域跳电视频道号，电台域跳电台序号
- **双域独立记忆**：上次电视频道、上次电台、上次所在域分别存；启动恢复的是"上次所在域 + 该域上次频道"；通知栏/锁屏的上一台/下一台也只在当前域内切
- **电台播放页**（12.3）在音频模式（电台域全部频道）下出现；电视域为视频模式，不进播放页
- **跨域唯一通道：「切回视频 / 去听音频」**——伴音频道播放页可一键跳电视域同频道视频版；电视播放中若该频道存在伴音流，OSD/面板出现"去听"入口。这是两域间唯一合法跳转

### 12.7 电视/电台切换冲突防线（定稿）

> 原则：全 App 只有一个 Player、一个 VideoController，任何内容切换（换台/切电台/切回视频/投屏结束回直播）必须走唯一入口 `switchTo(channel)`，内部执行"退场清单 → 进场清单"两段式。

| 冲突点 | 收法 |
|---|---|
| 两路声音重叠 | 先 pause 旧流再 open 新流，串行切换 |
| 视频纹理残留 | 电视→电台时视频 widget 移出渲染树（非隐藏），纹理自然释放 |
| WebView 内存残留 | WebView 为独占模式，切走必销毁实例，返回再重建 |
| 音频焦点 | 每次 open 后重新请求 audio focus，一个播放器一个焦点 |
| 后台策略错位 | 切台完成瞬间更新策略：tv→安卓小窗路线，radio→后台音频路线，策略跟内容走 |
| 投屏中切台 | 投屏独占输出，切域请求弹提示"请先断开投屏"，不允许半路切 |

- 状态机 `PlaybackMode: tv / radio / webview / cast` 四态，跳转有限可枚举；退场/进场顺序保证只在 switchTo 一处实现（与焦点协调器同一哲学：冲突源于多入口，收成单门即根治）
- 电视↔电台互切耗时用 OSD 连接状态提示（与换台防抖 OSD 同组件），避免"按了没反应"感

### 13.5 WebView 直连升级线：嗅探流并入线路体系（定稿）

> 沿用户现有源码设计（页面直播流嗅探 → 内部播放器播放 / 失败回退网页播放），但**不做独立切换按钮**——嗅探到的流作为该频道的"线路"并进步进器，WebView 页面本身永远作为最后一条兜底线路。

- **线路列表示例**：`1/3 直连流1080P ｜ 2/3 直连流720P ｜ 3/3 网页播放`——切换复用已有线路步进器/菜单，零新增 UI
- **自动择优 + 回退链**：优先直连线路 → 失败换下一条直连 → 全失败则重开页面**重新嗅探**（流地址常带时效 token）→ 仍失败落网页线路；挂在播放哨兵 + 分级重载机制上，不新增机制
- **嗅探实现**：WebView 资源请求拦截（m3u8/mp4 特征）+ 注入 JS 扫描 video/XHR，结果按频道缓存
- **模式可用性**：仅 WebView 频道；投屏中禁止（无页面活动）
- **线路来源统一模型**：线路 = 用户配置源 + 页面嗅探流 + 网页兜底，三种来源对界面同构。**排序按频道策略，非全局规则（修正：加密流站点直连是死路，不是首选）**：
  1. **已知加密站**（央视频/央视网等源内标注 `player=web` 的 WebView 频道）：**网页播放第一**，分辨率切换走页面内注入 JS（沿用现有设计）；嗅探流默认不并线（明知加密不试错）
  2. **普通网站**（结构未知）：直连流在前、网页兜底——普通 HLS 嗅出即可播，升级通道对此类生效；画质由 qualityLabel 实测补全（播前"自动"，播起显示真实分辨率）
  3. **电视直连频道**：用户配置多源线路，原机制
- **失败自动学习**：未声明策略的频道直连花屏/失败 → 自动落回网页线路并**记住该频道网页优先**，下次直接走网页；手动在线路菜单选直连成功则覆盖记忆（手动永远优先于自动学习）

## 十四、版本与发布规范（定稿）

### 14.1 语义版本（SemVer）

- 格式 `主.次.补`（例 2.1.3）：主=架构级换代（本次大改造即 2.0）；次=功能级（新增电台/字幕等）；补=修 bug（严禁三位数膨胀）
- 预发布用后缀不占位：`2.1.0-beta.1`、`2.1.0-rc.1`（rc=发布候选，全量验证通过才转正）
- **版本号唯一来源 = git 标签**：App 显示版本、CI 打包命名全部从标签自动读取，杜绝任何工具手改版本号

### 14.2 CI 三级流水线

| 触发 | CI 行为 | 产物 |
|---|---|---|
| 每次 push | 编译 APK + Windows/Linux 包 | 挂构建记录供验证，不生成 Release（版本 `2.1.0-beta.N`，N=构建号自动递增） |
| tag `v*-rc.*` | 同上 | GitHub **Pre-release**，试装验证 |
| tag `v*.*.*` 正式 | 同上 | 正式 Release（必须经 rc 验证后由用户手动打标） |

### 14.3 决策记录：不集成第三方"云端解密"模块

- 背景：个别 IPTV 应用在云端部署央视频解密代理，向客户端下发可直连流地址
- **否决理由**：① 命脉在第三方服务器（关停即功能整体瘫痪，且无替代源可换）；② 绕过技术保护措施再分发的法律暴露面与产品化传播不匹配；③ 依赖对方与防护改版的军备竞赛，属已否决的"脆弱依赖"模式
- **替代**：加密站点按 13.5 网页优先（官方播放器，无解密、稳定）；WebView 启动速度用预热/缓存等正规手段优化；官方公开流（若有）mpv 原生可播，无需解密

### 14.4 WebView 黑屏治理（实测问题驱动）

> 实测：Windows 端 WebView 播央视频出现 30 秒以上黑屏，切台依旧。三类病因与对症：

| 症状特征 | 病因 | 对策 |
|---|---|---|
| 整页全黑（无任何网页元素） | 页面加载被第三方脚本卡死 | 请求过滤（见下） |
| 网页在、视频区黑 | 高峰 CDN 拥塞/流慢 | 哨兵自动重载 + 等待状态显示 |
| 网页在、视频黑、CPU 高 | WebView 视频硬件合成未走通 | 渲染模式排查（to hand：远程调试 chrome://inspect 定位） |

**治理四件套**：
1. **WebView 预热**：启动即后台预建实例 + 预载常用站点，切到 WebView 频道直接切前台，砍掉黑屏大头；单实例复用，切台只换 URL 不重建
2. **请求过滤**：拦截广告/统计类第三方请求（规则表维护），页面加载提速一倍以上且降低卡死概率
3. **切台去重**：同域切台保留 cookie/会话缓存，避免每次从头握手
4. **哨兵兜底**（已有 12.x）：15 秒无画面自动软重载→硬重载，OSD 显示"正在连接·已等待 X 秒"，杜绝"死机了还是在转"的迷茫

### 14.5 老系统兼容：Win10 家庭版 1607 的 WebView（定稿）

- **实测结论（用户已验证）**：集成 WebView2 Runtime 与系统自带同样失败；CEF 插件方案黑屏不可用。根因是 Flutter 默认插件依赖系统 WebView2（要求 Win10 1803+），1607 不满足
- **最后一次便宜尝试（可选）**：CEF 黑屏最常见死因是 GPU 合成失败——加 `--disable-gpu`/swiftshader 软渲染参数再验一次（约 30 分钟）；变亮则老系统写死该参数，仍黑则彻底关闭此路线
- **最终降级设计（无论上项结果）**：
  1. 启动检测 WebView2 Runtime 缺失 → 明确提示"网页播放已停用"，不裸奔
  2. **WebView 停用机器上网页频道不死透**：线路体系中移除"网页线路"，剩余直连线路照常可用——央视系公开 HLS 流 mpv 原生可播，"网页优先"频道自动降级为"直连优先"，老机器变成"无网页模式的完整版"而非残废版
  3. 旁路建议保留：无锁版本理由时升级 Win10 22H2（家庭版免费）
